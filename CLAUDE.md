# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ComPoM is an R package that fits Poisson-multinomial models to compositional count data (length/age
frequencies) to standardise compositions for non-representative sampling and scale them to total
catch. Backends are `brms` (Bayesian/Stan) and `sdmTMB` (ML/TMB, optionally with spatial and
spatio-temporal SPDE fields). `README.md` has the workflow table and usage examples.

## Commands

```r
devtools::document()                                   # regenerate NAMESPACE / man (roxygen2)
devtools::test()                                       # all tests
devtools::test(filter = "post-proc")                   # one test file (tests/testthat/test-post-proc.R)
devtools::check(vignettes = FALSE)                     # as in CI (R-CMD-check.yaml)
covr::report(covr::package_coverage())                 # coverage
```

Tests fit real brms (1 chain, 200 draws) and sdmTMB models in `tests/testthat/helper-sim.R` and
`helper-sim-truth.R`, which are sourced before every test file, so even a single test run pays that
fitting cost. brms tests call `skip_if_no_brms()` (skipped without `rstan`). The spatial fixture needs
distinct locations per year and a real spatial/year/season signal, otherwise the sdmTMB Hessian is
not positive definite and `predict(nsim)` fails. `ex_comp`/`ex_catch` (`data-raw/ex_data.R`) are used
by the examples, README and `test-workflow.R`.

CI (`.github/workflows`): `R-CMD-check` (multi-OS, plus a check that `man/`/`NAMESPACE` are current),
`test-coverage`, `vignettes` (renders all vignettes), `pkgdown` (GitHub Pages), `release` (on `vX.Y.Z`
tags, notes from `NEWS.md`). Add a `NEWS.md` entry for user-visible changes.

Vignettes are slow (Stan/TMB fits) and not built in CI. `vignettes/scenario_results.csv` is
generated by `vignettes/run_scenarios.R` (run from `vignettes/`, uses `scenario_helpers.R`) and
read by the "Scenario Comparison" section of `spatial_bias_simulation.Rmd`.
`SCENARIO_SMOKE=1 Rscript run_scenarios.R` runs a ~15 s smoke version.

## Architecture

Pipeline, all in `R/`:

- `pre_proc.R`: `data_prep()` aggregates counts to stratum x bin (adds zero counts and stratum
  totals; grouping variables become factors, including coordinates, so convert to numeric before
  building an sdmTMB mesh). `parse_form()` turns the term arguments into a model formula
  (`ffx_form` = bin-specific fixed effects, `re_form` = bin-specific IID random effects, `cvars`/`spl`
  = covariate smooths, mesh/`time`/`coords` = spatial fields). `fit_model()` builds the formula and
  fits with either backend.
- `post_proc.R`: diagnostics and plots (`post_pred_group`, `Fx_plot`, `cvar_smooth_plot`,
  `spatial_field_plot`) and the scaling step. `scale_comps()` predicts numbers-at-bin draws for strata
  with known catch/CPUE. `scaled_comp_plot()` / `scaled_ridge_plot()` aggregate draws to
  catch-weighted compositions.
- `helpers.R`: small shared utilities (`gmean`). Simulation-only helpers (`Selectivity`,
  `scaled_comp_comp`) live in `vignettes/vignette_helpers.R`, not in the package.

`scale_comps()` modes: `mode = "catch"` is catch weighting (all terms, including `re_form` random
effects, at stratum levels, weighted by catch). `mode = "index"` predicts the population that a
CPUE index describes. Terms in `selectivity` and the `re_form` random effects are set to
references, and all other terms are predicted at the values in `grid` (one row per time step, or per
cell and time step for spatial fits), weighted by `weight`. Every `ffx_form`/`cvars` term must be in
`selectivity` or in `grid`. `remove_nuisance = TRUE` is a deprecated alias. The design is in
`dev/scale-comps-index-mode-plan.md`.

For spatial models, `scale_df` must contain the coordinates, and the time column must have the same
class (e.g. factor) as in the model data.

## Repo notes

- `*.bak` files (`R/post_proc.R.bak`, `vignettes/*.bak`) are scratch copies, excluded via
  `.Rbuildignore`. Do not edit them or treat them as source.
- `man/` and `NAMESPACE` are roxygen-generated (roxygen2 8.1.1). Edit the roxygen comments, not the
  Rd files.
- Large data files in `vignettes/` (`*.RData`, `*.rda`, `*.rds`) and `figure/` are untracked working
  material.
